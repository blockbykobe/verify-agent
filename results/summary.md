# Experiment summary: A / C / D / E

- **A** — single answer, nothing executed before scoring.
- **C** — self-verification: the model writes solution + its own test, sees test output, up to 3 attempts.
- **D** — independent verifier: a separate model call (fresh context) writes a test from task.md only, BEFORE any solution; the solver never sees the test, gets only PASS/FAIL + its own stdout, up to 3 attempts.
- **E** — oracle upper bound (unrealistic): the verifier is the hidden check.sh itself; solver gets PASS/FAIL + its stdout.

Model: qwen2.5-coder:7b (Ollama, CPU), temperature 0.7, 15 tasks (10 solve / 3 abstain / 2 ask_human).
Hidden `check.sh` is used **only** for final scoring in a clean container and never shown to the model; in A, C, D it is never used as feedback (in E it is the verifier by design).
Values: mean ± sample std over runs (min, max). Generated by `analyze.py` from `results/*.jsonl`.
